# 小说整理归档 · Novel archive

把一个 DeepSeek 公开分享的对话，整理成四类交付物：**完整对话记录**、**人物设定**、**情节发展**、**续接包**（含 zip）。
再加一个对话框里的小面板：贴链接、补自己的人设和补充文件、整理完**一键接着往下写**。

适合：长对话写出来的小说/角色扮演记录，想存档、想接着写、怕换对话就忘事。

## 两个入口

**对话框里的小面板（推荐）**：输入框下方有一个「📚 小说续接」小按钮（插件装好或更新后刷新一次页面）。

1. 贴分享链接；
2. 选自己的工作目录（点「选择…」可以在目录树里点，不用手打路径）；
3. 需要的话，选「原始人设」和「补充文件」（txt / md / docx / html，可多个；人设在附件设定之前，补充文件在之后）；
4. 「开始整理」——抓消息、下附件、切分章块、把三份设定合成 `share/setting.txt`；
5. 「一键继续（第 N 轮）」——插件把 07 那段接续指令直接放进输入框并发送，模型就从第 N+1 轮接着写。**不需要先手写 `novel.json`**：没有时会按设定和最后几轮自动推断一份，用过一眼再改。

「生成续接包」按钮刷新 03 与续接包 00—07 和 zip。
「记忆」区块可以生成、改写、保存滚动记忆卡，也可以重建索引。

**agent 工具**：同一套实现也暴露成工具，适合让 agent 全自动跑。

## 工具

| 工具 | 做什么 |
| --- | --- |
| `novel_archive_extract` | 分享链接（可再加 `settingPaths` / `extraPaths` 或面板上传的文件）→ 下载全部消息与附件 → 写出 `01_完整对话记录.md`、`analysis/turns.jsonl`、`analysis/chunks/chunk_NN.md`（每块一章素材）、`share/setting.txt`（人设＋附件＋补充合并）、`share/uploads/`、`PLAN.md` |
| `novel_archive_search` | 在已抽出的轮次里按关键词/正则查，带轮次与上下文，用来凑人物档案、核对事实 |
| `novel_archive_status` | 报告进度：分章块几块、beats 写了几块、novel.json 还缺哪些字段、02/03/zip 有没有 |
| `novel_archive_state` | 同样信息的紧凑 JSON：轮数、第几轮结束、下一轮、分章/beats、续接包与 zip、novel.json 的当前场景 |
| `novel_archive_continue` | 生成可整段粘贴的接续指令（身份、当前这一刻、记忆锚点、**工作目录里的设定**、**记忆卡与检索片段**、最近 8 轮原文、写法、怎么开始），返回接第几轮与是否推断，并写出 `续接包/07_一站式接续_整段粘贴.md/.txt` |
| `novel_archive_memory` | 滚动记忆：`status` 看覆盖到哪轮、`digest` 按原文抽一段底稿、`save` 存成 `记忆_起始-结束.md`（自动重建索引）、`index` 重建 `记忆/00_索引.md`、`recall` 按关键词检索记忆卡/章节/设定 |
| `novel_archive_kb` | 模块化知识库：`init` 建骨架、`index` 重写 `00_知识库.md`、`read` 看模块清单或某个模块全文、`sync` 从 beats/人物设定重建剧情章节与角色/规则/时间线并补事件簿、`append` 往某个模块追加一段 |
| `novel_archive_assemble` | 装配：用真实名字重建 01、由 beats 拼出 03、同步知识库、生成续接包 00—07（md+txt）、打 zip |

## 用法

```text
1. novel_archive_extract({ url, settingPaths: ["…/原设定.docx"], extraPaths: ["…/补充规则.md"] })
2. 对每个 chunk 派一个子代理，写 analysis/beats/block_NN.md（第N章）与 analysis/chars/chunk_NN.json
3. 写 02_人物设定.md
4. novel_archive_assemble({ outDir })
5. 要接着写：novel_archive_continue({ outDir })（面板里是一键完成）
   每写 20—30 轮：novel_archive_memory({ outDir, action: "digest", from, to }) → 改写成五行 → action: "save"
```

`novel_archive_extract` 与 `novel_archive_assemble` 之间的分章与人物设定是模型工作，插件只负责所有确定性部分：抓取、解析、切块、拼装、打包、续接 prompt 组装。
`novel.json` 缺失时 `continue` / `assemble` 会自动推断一份并落盘（`_inferred: true`），名字、年龄、身份、写法来自设定，当前场景与好感度来自最后几轮。

## 设定与记忆（防漂移）

续接 prompt 每次都是**现读磁盘**，所以改文件下一轮就生效：

- `设定/`：放你自己的人设、规则、补充材料（`.md`/`.txt`）。根目录下名字以 `人设` `规则` `设定` `补充` `写作` `限制` `世界` 开头的文件、`02_人物设定.md`、以及对话附件里的 `share/setting.txt` 也会被读进来。每份最多取 2200 字，合计 7000 字。
- `记忆/`：滚动记忆卡 `记忆_开始轮-结束轮.md` + `00_索引.md`。每次续接自动带最近两张卡与索引节选，再按「她上一句 + 未收线索」检索片段。

面板里：状态块下方「记忆（滚动记忆 / 知识库）」——填起止轮次 →「生成记忆卡」得到底稿 → 在文本框里改成五行 →「存为记忆卡」（会写文件并重建索引）。


## 知识库（工作目录就是大脑）

整理完，工作目录自动长出这套模块化目录；续接时按模块读，写完再把新发生的事补回去：

| 目录 | 放什么 | 谁写 |
| --- | --- | --- |
| `00_知识库.md` | 总索引：模块清单、当前状态、AI 的读取顺序 | 插件 |
| `01_剧情/` | `00_分卷与章目.md` + `章节/第NN章_标题.md`（概述/节点/关系刻度/对白，来自 beats） | 插件（装配时） |
| `02_角色_他/` | AI 扮演的人：身份、年龄、性子、禁忌 | 插件从 novel.json + 人物设定里抽 |
| `03_角色_我/` | 用户演的这个人：身份、小名、关系 | 同上 |
| `04_事件/事件簿.md` | 一条一条带轮次：她第一句 → 他第一句 | 插件增量追加（每次续接/同步） |
| `05_时间线/` | `当前.md`（这一幕：轮次/时间地点/正在发生/感情进度/他最后一句）+ `时间线.md` + `地点.md` | 插件 |
| `06_特殊事件/` | 大节点：葬礼、绑架、ICU、结婚、远行 | 插件/模型 |
| `07_其他人物/` | 配角与来历、和两人的关系 | 插件从人物设定里抽 |
| `08_特殊物品/` | 戒指、手表、信件、材料这类有分量的物件 | 插件/模型 |
| `09_生活物品/` | 家里的东西、吃穿用度、习惯细节 | 模型 |
| `10_规则/输出规则.md` | 用来的写法与输出要求（最高优先级） | 插件从设定里抽 |
| `11_记忆卡/` | 滚动记忆 `记忆_开始轮-结束轮.md` + `00_索引.md` | 插件自动 + 面板/模型 |
| `12_情感/` | `情感要求.md`（怎么处理情感输出，逐条带出处）、`情感样本.md`（原句+轮次，按场景分组）、`情感曲线.md`（好感度变化） | 插件 |
| `13_伏笔/` | 还没落地的事：交换材料、酒席、没认的话；带来源 | 插件（从最新两章里筛） |
| `14_语感/` | 按场景的原句摘录 + 常用词/禁词 | 插件 |
| `15_来源/` | 每份设定从哪来、什么时候写进来、第几轮 | 插件 |
| `16_世界观/` | 时代、地方、规矩、阶层、钱与身份、场所与家里结构；人物为什么只能这样活 | 插件 + 模型 |
| `17_场景/` | 一个地方一份文件：住处、医院、公司、学校、酒店、老家、外地的布局、光线、家具、常出现的人（每条带轮次） | 插件（从原文抓）+ 模型 |

续接 prompt 的顺序固定为：一 你我是谁 · 二 现在这一刻 · 三 你要记住的事 · **四 知识库（索引 + 按模块取用）** · 五 工作目录里的设定 · 六 记忆卡与检索片段 · 七 最近八轮原文 · 八 写法 · 九 怎么开始。
知识库总预算约 15500 字：规则 2200 → 世界观 1000 → 情感 1800 → 场景 1400 → 角色 1800×2 → 时间线/特殊事件 → 最近两章剧情 2200 → 语感 1000 → 伏笔 800 → 事件簿 1000 → 其他人物/物品；超出的部分按这个顺序截断。嵌进 prompt 时这些文件的标题会自动降两级，不会打乱 prompt 的章节结构。

面板里「知识库（工作目录就是大脑）」下面三个按钮：**建知识库**（只补骨架）、**同步知识库**（按档案重写角色/规则/时间线/情感，补新事件）、**重建索引**。

### 规则按出处拆开

`10_规则/` 不再只放一份大文件：整理与同步时，把合并进 `share/setting.txt` 的每一段拆成 `来源NN_<名字>.md`，文件头写 `> 来源：…` 与写入时间，另有 `00_规则清单.md` 汇总「哪份规则从哪来、多少字」；`输出规则.md` 保留为兜底（从人物设定与 novel.json 抽的写法要求）。改哪条就改那一份，改完点一次「同步知识库」即可，不必重跑整个整理。

### 世界观（16_世界观）

写之前先看这里：时代与地方、外面的规矩、阶层与身份、场所（住处几层、书房和客厅在哪）、以及这个世界**不成立**的东西（没有黑帮火并、没有超现实）。人物的一切选择都受它约束，写的时候不要越出这个世界。整理时自动从人物设定的「故事世界」「关键地点」和上传设定里的对应段落生成，缺了就用通用现实设定兜底，之后可以在面板里改。

### 场景（17_场景）

写一场戏之前先翻这里。`00_场景索引.md` 是目录，每个地方一份文件，例如 `01_住处.md`：

- **这里是什么样子**：从原文里抓的「外貌句」——只亮着一盏灯的桌面、落在窗帘上的影子、走廊尽头的房间、玄关柜上的东西，每条后面带轮次。
- **常出现的人**：住处是家里人、管家、司机；医院是医生和护士；公司是助理与同事。
- 住处那份还会把人物设定里「关键地点」的条目抄进来。

抓取规则：只认带窗、门、墙、灯、沙发、桌、柜、床、走廊、台阶、电梯、地毯、窗帘、楼上下、味道、光线这类「像在写地方」的句子，每处最多 16 条，按 18 字去重。认得的地方先有这九类：住处、医院、公司、学校、酒店与席面、机场与路上、老家、外地、度假地；面板里手写的文件会一并列进索引。每 20 轮续接时自动重认一次，新出现的地方、新写的屋子细节会自己补进去。

### 上传资料与对话输出怎么自动更新

| 来源 | 什么时候更新 | 更新什么 |
| --- | --- | --- |
| 用户上传的人设/补充/规则 | 整理、点「同步知识库」时 | `share/uploads/` 原文、`share/setting.txt` 合并稿、`10_规则/` 按出处拆分、`设定/` 镜像 |
| 对话输出（新轮次） | 每次「生成续接包 / 一键继续」 | `05_时间线/当前.md`、`04_事件/事件簿.md`、`12_情感/情感样本.md`、每满 20 轮一张 `11_记忆卡/`、每满 20 轮重认 `17_场景/` |
| 章节、角色、规则、伏笔、来源、世界观 | 点「同步知识库」或装配时 | 全量重建 |
| 角色新侧面 | 模型自己调 `novel_archive_kb`（`append`, `module:"hero"`） | 追加进 `02_角色_他/角色_他.md` |

一句话：**上传的东西整理时就进库，对话框里新写的东西每次续接都自动往回写；重活留给你点一下，或者交给下一次装配。**

### AI 怎么认领角色、怎么更新自己的人设

续接 prompt 第一节直接写明「你就是<主角名>，不是旁白、不是助手」；第二节紧接现在这一刻；知识库第五节里放着 `02_角色_他/角色_他.md`。

- **思考链也在角色里**：prompt 里有一条硬要求——「你的思考也用他的眼睛：不写『作为 AI』『我需要扮演』『用户想要』这类话，不去分析规则，只按他知道的事、他在意的事往下想」。所以复述场景阶段之后，它的推理也应该以他的口吻、他的顾虑展开。
- **自己更新人设**：`novel_archive_kb` 的 `append` 可以写 `module:"hero"`，追加进 `02_角色_他/角色_他.md`。prompt 里明确允许它这么做——出现新的习惯、说法、对她的新态度时，回复后追加一条，只追加不覆盖，一轮最多一条；你说「更新人设」，它就把这一段里的侧面整理成几条写进去。装配/全量同步会重写角色文件，所以长期的东西还是回到 `02_人物设定.md` 或 `设定/` 里改。

### 上传与对话输出怎么进库

- **上传**：面板选的人设/补充文件，原文存 `share/uploads/`，合并文本写 `share/setting.txt`，并按段拆进 `10_规则/`；装配时同一份也镜像进 `设定/`。
- **对话输出**：每次「生成续接包 / 一键继续」都会做一次轻同步——刷新 `05_时间线/当前.md`、把新轮次追加进 `04_事件/事件簿.md`、按最近轮次重写 `12_情感/情感样本.md`，并且**每满 20 轮自动落一张** `11_记忆卡/记忆_XXXX-YYYY.md`（用原文抽底稿）。全量重建（章节、角色、规则、伏笔、来源）走「同步知识库」。

## 宿主接口（面板用）

前缀 `/novel-archive/api`，GET/POST 都返回 `{ ok: true, value }` 或 `{ ok: false, error: { message } }`：

| 路由 | 说明 |
| --- | --- |
| `GET config` | `cwd`、`home`、默认输出目录 |
| `GET browse?path=` | 目录选择器：`{ path, parent, home, dirs:[{name,path}] }` |
| `GET state?dir=` | 一个整理目录的快照（`novel_archive_state` 同源） |
| `POST extract` | `{ url, outDir, chunkSize, uploads:[{name,kind:"setting"\|"extra",base64\|text}] }` |
| `POST continue` | `{ dir, tailRounds }` → `{ prompt, nextRound, hero, girl, affection, inferred, … }` |
| `POST assemble` | `{ dir, tailRounds, zip }` → 报告，`inferredNovel` 表示是否用了推断的 novel.json |
| `GET novel?dir=` | `novel.json`（缺失时返回推断的那一份，`inferred: true`） |
| `GET memory?dir=` | 记忆覆盖情况与卡片列表 |
| `POST memory` | `{ dir, action: "digest"\|"save"\|"index", from, to, every, cardTitle, cardText }` |
| `GET recall?dir=&q=` | 关键词检索（记忆卡 / 章节 / 设定） |

## novel.json

它决定所有交付物的口径。字段：

- `title` / `userLabel` / `aiLabel`：书名、女主名、男主名（用对话里真实的称呼）
- `user` / `ai`：`name` `age` `identity` `home` `body` `callName` `traits`
- `relationship`：两人关系一句话
- `current`：`round` `day` `place` `scene` `lastUserQuote` `lastAiQuote` `affection` `relationshipNote` `openThreads[]`
- `rules`：`pov` `lengthLine` `style[]` `deny[]` `statusBar{fields,sample}`
- `memory`：`people[]` `events[]`(带 round) `objects[]` `promises[]`(带 round) `mistakes[]`
- `voice`：`samples[{label,lines[{round,text}]}]` `allowWords[]` `denyWords[]` `nowTone[]`
- `volumes`：`mainline` `lines[{line,content}]` `items[{title,from,to,intro}]`；也接受「按章号分卷」的写法（`volumes: [{name, chapters:[1,2,…], intro}]`），装配时会换算成轮次区间
- `pack.tailRounds`：续接包里逐字保留的轮数（默认 60）
- `oneShotMemory[]`：07 里「你要记住的事」直接列这些

`analysis/novel.example.json` 是空壳。一键续接不再强制要求它：没有时自动推断（`_inferred: true`、`_note` 里说明），面板会提醒你过一眼；想精修就打开根目录的 `novel.json` 改。

## 路径与文件

- 工具里的相对路径按**当前会话的工作目录**解析；面板里填的「工作目录」就是输出目录，会记在浏览器本地，下次不用再填。
- 上传文件支持 `.txt`、`.md`、`.markdown`、`.docx`、`.html`（PDF 请先转成 docx 或 txt，插件不解析 PDF）。
- 面板上传的文件原样留在 `share/uploads/`，同时镜像一份到 `设定/`（方便直接改）；合并后的设定在 `share/setting.txt`：一、原始人设 → 二、对话附件里的设定 → 三、补充文件。

## 限制

- 只能读**公开分享**的链接（未登录接口）；私密对话读不到。
- 附件只认第一个（docx/文本）；docx 用内置的最小 unzip + XML 取文字，复杂表格会丢格式。
- 一键续接不是自己写小说：它只把「接续指令」送进输入框并发送，后续由当前对话里的模型写；`novel.json`、`设定/`、`记忆/` 与最近的原文决定像不像。
- 自动推断只认设定里的 `姓名：` 这类字段和对话里「我叫…」的自述；推断出来的名字/年龄/场景要自己核一眼。
- 面板与工具都会跑同一个 `runExtract`；长对话（几千轮）抓取约几秒，分章与人物设定仍要模型逐块写。
- 知识库不是数据库：正文靠文件与索引，检索是关键词匹配（不是向量检索）；知识库总预算约 12000 字，太长会被截断，所以剧情只取最近两章、事件簿只取最新一段。
- 「保存增补」是插件在续接/同步/装配时按档案确定性写入；角色扮演中的模型没有文件写权限，不会自己改知识库。新出现的细节要么写进 `novel.json` 的 `current`，要么用 `novel_archive_kb` 的 `append`，要么在面板里手改文件。
