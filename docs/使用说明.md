# 小说续接知识库 · 插件使用说明

> 适用版本：dsh-novel-archive 0.7.0
> 位置：插件目录（本地 clone 或解压后的 `dsh-novel-archive/`）
> 一句话：**把一个 DeepSeek 分享链接，整理成工作目录里的模块化知识库；然后在这个对话里点一下，AI 就以角色身份接着往下写。**

---

## 一分钟开始

1. 重启一次 DSH（宿主代码改过），刷新页面。
2. 输入框下面点「📚 小说续接」。
3. 粘分享链接，选工作目录，需要的话上传原始人设/补充文件，点「开始整理」。
4. 等它跑完（5 万字以上一般几秒到一分钟），点「生成续接包」。
5. 面板里看到「第 N 轮结束、下一轮第 N+1 轮」之后，点「一键继续」——它把接续 prompt 放进输入框并发送，你直接写第一句动作或台词。

---

## 一、装与更新

插件是本地 link 安装的，改代码不用重新打包，但要重装一次才会加载：

```text
plugin_manager  action=install_bundle  target=<插件目录>/dsh-novel-archive
```

装了新版本之后：

- **宿主代码（工具、整理、装配）**：需要重启 DSH。
- **客户端代码（面板按钮）**：刷新页面。

排障时先看一条：`list_bundles` 里 `dsh-novel-archive` 必须是 `"enabled": true`。见过一次「装完是 enabled:false」，表现就是面板按钮不出现、`/novel-archive/api/*` 全部 404。修法是再 `set_bundle(enabled=true)`。

## 二、面板：📚 小说续接

打开后从上到下是：

| 区域 | 字段 | 说明 |
| --- | --- | --- |
| 整理 | 分享链接 | `https://chat.deepseek.com/share/xxxx`，只读公开分享 |
| | 工作目录 | 档案放哪儿；点「选择…」用目录树挑，默认是当前工作区下 `小说整理` |
| | 原始人设 | 可选，多选；.txt / .md / .docx / .html |
| | 补充文件 | 可选，多选；规则、限制、输出要求都放这里 |
| | 开始整理 | 抓取 + 解析 + 切块 + 建知识库骨架 |
| 装配 | 生成续接包 | 重建 01/03/续接包，并把所有模块同步一遍 |
| 状态 | 轮数 / 结束轮次 / 分章 / chunks | 一眼看整理到哪儿了 |
| 记忆 | 覆盖轮次、生成记忆卡、重建索引 | 滚动记忆的手动入口 |
| 知识库 | 建知识库 / 同步知识库 / 重建索引 | 17 个模块的维护入口 |
| 一键继续 | 按钮 | 生成 prompt → 填入输入框 → 发送 |

工作目录存在浏览器 localStorage 里，下次打开还是上次那个。

## 三、第一次整理会产出什么

```text
<工作目录>/
├─ 00_知识库.md              ← 总索引：每个模块有多少文件多少字、现在写到哪儿
├─ 01_剧情/                  ← 分卷与章目 + 章节/第NN章_标题.md（完整保存，不是梗概）
├─ 02_角色_他/               ← AI 扮演的人（它可以自己追加）
├─ 03_角色_我/               ← 你扮演的人
├─ 04_事件/事件簿.md         ← 一条一件，带轮次
├─ 05_时间线/                ← 当前.md（这一秒）+ 时间线.md + 地点.md
├─ 06_特殊事件/              ← 绑架、ICU、领证、远行这类大节点
├─ 07_其他人物/              ← 配角设定与剧情
├─ 08_特殊物品/              ← 戒指、手表、材料这些有分量的东西
├─ 09_生活物品/              ← 吃穿用度、屋里有什么
├─ 10_规则/                  ← 你上传的规则，按出处拆成一份份 + 00_规则清单.md
├─ 11_记忆卡/                ← 滚动记忆：记忆_XXXX-YYYY.md + 00_索引.md
├─ 12_情感/                  ← 情感要求（带出处）/ 情感样本（按场景）/ 情感曲线
├─ 13_伏笔/                  ← 还没落地的事
├─ 14_语感/                  ← 按场景的原句摘抄，写作前找语气
├─ 15_来源/                  ← 每份设定的来历与写入时间
├─ 16_世界观/                ← 时代、地方、规矩、阶层、场所
├─ 17_场景/                  ← 一个地方一份：布局、光线、家具、常出现的人
├─ 01_完整对话记录.md        ← 逐字全记录，带思考过程
├─ 02_人物设定.md            ← 如果有，会被读进知识库当底稿
├─ 03_情节发展.md            ← 分卷 + 章目 + 每章概述与节点
├─ 续接包/                   ← 00—07 全套 + 03a/03b 拆分
├─ 小说续接包.zip
├─ share/                    ← 原始 content.json、附件、上传文件、setting.txt
└─ analysis/                 ← turns.jsonl、fulltext.txt、chunks/、beats/、chars/、stats.json
```

`share/setting.txt` 是三段合并稿：`# 一、原始人设`（你上传的）、`# 二、对话附件里的设定`（分享里带的 docx）、`# 三、补充文件`。

## 四、人设从哪里来：novel.json

`<工作目录>/novel.json` 是这套东西的「总设定」：书名、两人姓名年龄身份、关系、当前这一幕、写法规则、分卷。有两种来源：

1. **自动推断**（推荐起步）：目录里没有 novel.json 时，插件会从 `share/setting.txt` 和最近几轮原文里推出来，文件名旁会标 `_inferred: true`，同时给出提醒「看一眼名称和当前场景再改」。它会读：
   - `女主人设` 前后切的男/女两块设定；
   - 用户文本里的「我叫…」「小名…」（对话中途改过名字，推断会以后来的自述为准，不是附件里的旧名）；
   - 年龄会往后推（附件写 18 是起点，读到「过了生日就是二十岁」就改成 20）；
   - 好感度取最后一轮的 `好感度 NN%`；当前场景取最后一轮的动作与最后一句台词。
2. **手写/改过**：有 novel.json 就直接用，不再推断。想改人物、场景、写法，改这个文件或者让它推断一次再改。

删除 novel.json 会触发下一次重新推断——这是「我发现它叫错名字了」最快的修法。

## 五、一键继续：它到底做了什么

点「一键继续」时：

1. 从磁盘现读 `设定/`、`share/setting.txt`、17 个知识库模块、最近两张记忆卡、关键词检索片段；
2. 先做一次**轻同步**（见第七节），保证「当前这一幕」是最新的；
3. 生成 `续接包/07_一站式接续_整段粘贴.md/.txt`；
4. 把 prompt 通过会话的 `inputActions.setDraft()` 写进输入框，再 `submit()` 发出去。

prompt 的九段固定顺序：

| 段 | 内容 |
| --- | --- |
| 一、你我是谁 | 两人姓名年龄身份、关系、称呼；**「你就是<主角名>，不是旁白、不是助手」** |
| 二、现在这一刻 | 第几轮结束、下一轮第几轮、时间、地点、正在发生什么、他最后一句、好感度 |
| 三、你要记住的事 | 他/她的身份、称呼、好感度、从第几轮接 |
| 四、知识库 | 索引 2600 字 + 按模块取用（规则→世界观→情感→角色→场景→时间线→特殊事件→最近两章→语感→伏笔→事件簿→其他人物→物品→记忆卡），合计约 15500 字 |
| 五、工作目录里的设定 | `设定/` 与 `setting.txt` 的原文 |
| 六、记忆卡与检索片段 | 最近两张卡 + 按当前场景关键词检索到的片段 |
| 七、最近八轮原文 | 逐字，含 ```` ```text ```` 状态栏——**语气靠这段，不靠规则** |
| 八、写法 | 视角、篇幅、禁词、状态栏四项、节奏 |
| 九、怎么开始 | 先两三句复述场景/好感度/上一句，然后停住等你说 |

想手动用：把 `07_…txt` 分割线后的内容整段复制，粘进任意对话也行（但没有工具的那个会话里，AI 不能写文件，回来点「同步知识库」补上）。

| 05 | `05_时间线/` | 当前这一幕、时间线、地点 | 插件 |
| 06 | `06_特殊事件/` | 绑架、ICU、结婚、远行这类节点 | 插件 |
| 07 | `07_其他人物/` | 配角与他们的来历 | 插件 |
| 08 | `08_特殊物品/` | 戒指、手表、材料 | 插件 |
| 09 | `09_生活物品/` | 吃穿用度、屋里有什么 | 插件 |

| 11 | `11_记忆卡/` | 滚动记忆，每 20 轮一张 | 插件 |
| 12 | `12_情感/` | 情感要求（带出处）、按场景的样本、好感度曲线 | 插件 |
| 13 | `13_伏笔/` | 还没落地的事 | 插件 |
| 14 | `14_语感/` | 按场景的原句摘抄 | 插件 |
| 15 | `15_来源/` | 每份设定的来历与写入时间 | 插件 |
| 16 | `16_世界观/` | 时代、地方、规矩、阶层、场所 | 插件 + 模型 |

读取顺序（进 prompt 的顺序）：规则 → 世界观 → 情感 → 角色·他 → 角色·我 → 场景 → 时间线 → 特殊事件 → 最近两章 → 语感 → 伏笔 → 事件簿 → 其他人物 → 特殊物品 → 生活物品 → 记忆卡。

预算 15500 字，超过按上面的顺序截断——所以「最近两章」比「半年前的事件」优先。

## 七、自动更新：什么会自己长出来

| 来源 | 什么时候跑 | 更新什么 |
| --- | --- | --- |
| 你上传的人设/补充/规则 | 整理时、点「同步知识库」 | `share/uploads/` 原文、`share/setting.txt` 合并稿、`10_规则/` 按出处拆分、`设定/` 镜像 |
| 对话新轮次 | **每次「生成续接包 / 一键继续」** | `05_时间线/当前.md`、`04_事件/事件簿.md`、`12_情感/情感样本.md` |
| 每满 20 轮 | 同上，自动触发 | 一张 `11_记忆卡/记忆_XXXX-YYYY.md`；`17_场景/` 重认一遍 |
| 章节、角色、规则、伏笔、来源、世界观 | 点「同步知识库」或下次装配 | 全量重建 |
| 角色新侧面 | AI 调 `novel_archive_kb`（`append`, `module:"hero"`） | 追加进 `02_角色_他/角色_他.md` |

一句话：**上传的整理时进库，对话框里新写的每次续接都往回写；重活留一次点击。**

## 八、AI 认领角色、思考链在角色里、自己更新人设

- prompt 第一段里有两句硬话：**「你就是<主角名>，不是旁白、不是助手」**、**「你的思考也用他的眼睛：不写『作为 AI』『我需要扮演』『用户想要』这类话，不去分析规则，只按他知道的事、他在意的事往下想」**。
- 写法段里有一条授权：出现新的习惯、说法、对她的新态度时，回复后调 `novel_archive_kb`（`action:"append"`, `module:"hero"`, `cardText:"一句话"`），**只追加、不改写、一轮最多一条**；你说「更新人设」，它把这一段整理成几条写进去。
- 注意：装配和全量同步会重写角色文件，所以定下来的东西要写进 `02_人物设定.md` 或 `设定/`，否则会被覆盖。

## 九、工具清单（给 agent 用）

| 工具 | 作用 | 关键参数 |
| --- | --- | --- |
| `novel_archive_extract` | 抓分享链接、解析、切块、建库 | `url`、`outDir`、`chunkSize=80`、`attachment`、`settingPaths`、`extraPaths` |
| `novel_archive_search` | 全文检索（带轮次与上下文） | `outDir`、`terms`、`regex`、`context=160`、`maxHits=3` |
| `novel_archive_status` | 整理到哪一步、能不能装配 | `outDir` |
| `novel_archive_assemble` | 拼 01/03/续接包/zip、全量同步知识库 | `outDir`、`tailRounds=60`、`zip` |
| `novel_archive_continue` | 生成接续 prompt 并写 07 | `outDir`、`tailRounds=8` |
| `novel_archive_state` | 档案状态 JSON（轮数、写没写、novel 摘要） | `outDir` |
| `novel_archive_memory` | 滚动记忆：status / digest / save / index / recall | `outDir`、`action`、`from`、`to`、`every`、`cardTitle`、`cardText`、`query` |
| `novel_archive_kb` | 知识库：init / index / read / sync / append | `outDir`、`action`、`module`、`file`、`cardText` |

> 参数名 `title` / `text` 是雷区：`novel_archive_memory` 早期版本用过 `title`，和宿主注入的工具标题字段撞名，会让整个会话第一条就 INVALID_REQUEST。现在统一是 `cardTitle` / `cardText`，别再改回去。

工具的相对路径按**当前会话工作目录**解析；面板的「工作目录」是输出目录，存在 localStorage。

### HTTP 接口（面板用的，也可以脚本调）

前缀 `/novel-archive/api`，返回统一是 `{ ok: true, value }` 或 `{ ok: false, error: { message } }`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/config` | 当前工作区、默认输出目录、平台 |
| GET | `/state?dir=` | 状态摘要 |
| GET | `/browse?path=` | 目录浏览（面板选择器用） |
| POST | `/extract` | `{ url, outDir, chunkSize, uploads }`，uploads 是 `[{name, kind, text/base64}]` |
| POST | `/assemble` | `{ dir, tailRounds, zip }` |
| POST | `/continue` | `{ dir, tailRounds }` → prompt |
| GET | `/memory?dir=` | 记忆卡覆盖情况 |
| POST | `/memory` | `{ dir, action: digest/save/index }` |
| GET | `/recall?dir=&q=` | 关键词检索（中文要 `--data-urlencode`） |
| GET | `/kb?dir=&module=` | 模块统计或某模块全文 |
| POST | `/kb` | `{ dir, action: init/index/sync/append }` |

## 十、常见问题

**面板里没有「📚 小说续接」**
1. 刷新页面；2. 重启 DSH；3. `list_bundles` 看 `dsh-novel-archive` 是否 `enabled:true`；4. 看 Settings → Plugins 里有没有报错。

**`/novel-archive/api/*` 全 404**
同上，九成是 `enabled:false`。`set_bundle` 打开后不用重启，路由立刻回来。

**一开新会话就 `Invalid schema for function …`**
某个工具参数名撞了宿主保留字段（历史上是 `title`）。改名重装即可；自查方法是用 `parameterSchemaSpecToJsonSchema` 把工具表整个转一遍。

**名字/年龄/称呼不对**
删掉 `<工作目录>/novel.json`，重新「生成续接包」触发推断；或者直接改 novel.json 再生成。

**它记得设定但语气变了**
07 里的「最近八轮原文」被截短了，或者记忆卡太多把原文挤掉。把 `tailRounds` 调大（默认 8），或手动把最近几段原文贴给它。

**知识库太长、prompt 溢出**
预算 15500 字，顺序固定；想保原文就把规则/事件的配额调小（`lib/kb.js` 的 `perModule`），或把不用的模块目录挪走。

**记忆卡不生成**
要满 20 轮才自动落一张；也可以面板里「生成记忆卡」手动出底稿，编辑后「存为记忆卡」。

**场景认错地方**
关键词法，不是语义理解。「楼上几家餐厅」会被归到住处。手写一份 `17_场景/xx.md` 覆盖，它会一起列进索引并进 prompt。

**AI 说「我翻了知识库」**
prompt 里已经写了「这些是记忆，不是情节：不要复述它们」，如果还出现，把这句话再贴给它一次。

**在纯聊天窗口里续写，AI 不能自己更新人设**
那个会话没有工具。回来点「同步知识库」，或让 agent 用 `novel_archive_kb` 写。

## 十一、限制与边界

- 只读**公开**分享页；需要登录的私聊拿不到。
- 只处理分享里的**第一个附件**；docx 用自写的最小 unzip + XML 取字，不解析 PDF。
- 分章、人物设定这类「要理解」的活仍然由模型做，插件只做确定的抓取、切块、拼装、打包——所以第一次整理之后要检查章节标题和概述。
- 情感/场景/伏笔靠关键词与规则抽，粗糙但稳定；要更准就手写覆盖，插件不会删你手写的文件。
- 一键继续只是把 prompt 送进输入框，正文仍是当前会话的模型写；「自动更新」也只能在插件运行时发生，AI 不能在聊天里凭空写盘。
- 关键词检索不是向量检索；中文查询走 HTTP 时要 URL 编码。
